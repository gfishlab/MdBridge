# 图片导入与 PicGo 设置设计

## 目标

在设置中提供可切换的图片导入方式。用户粘贴剪贴板图片时，可保存到本地或上传至 PicGo Server；粘贴已有的 HTTP(S) 图片链接时，直接插入 Markdown 图片语法。图片的 Markdown 描述可配置为无描述、文件名或固定自定义描述。

首次安装默认使用本地绝对路径。这样未保存的新文档也能立即插入可用图片，不会生成无基准目录的相对路径。

## 输入与输出

编辑器监听粘贴事件，按以下优先级处理：

1. 剪贴板包含图片文件：按当前导入方式写入本地或上传 PicGo，然后在当前光标处插入 Markdown 图片。
2. 剪贴板包含单个 HTTP(S) 图片链接：不下载、不上传，直接在光标处插入 Markdown 图片。
3. 其他文本与非图片数据：维持编辑器原生粘贴行为。

插入格式为 `![描述](图片地址)`；“无描述”输出 `![](图片地址)`。

## 设置模型

### 导入方式

- `absolute`：复制到 `~/Pictures/MDBridge`，插入绝对路径。首次安装默认此项。
- `relative`：复制到已保存 Markdown 文件同级的 `assets` 目录，插入相对路径。当前文档未保存时拒绝导入并提示先保存文档，绝不生成无效相对路径。
- `custom`：复制到用户选择的本地目录，插入该文件的绝对路径。
- `picgo`：上传至 PicGo Server，插入服务器返回的 HTTP(S) 图片链接。

本地文件名由时间戳、随机后缀与图片扩展名组成，避免覆盖原有图片。复制或上传失败时不改变文档内容，并给出明确状态消息。

### PicGo Server

- 默认地址为 `http://127.0.0.1:36677/upload`，可修改为兼容 PicGo Server 的上传地址。
- 客户端以 `multipart/form-data` 发送图片文件，字段名为 `list`。
- 接受 PicGo Server 的 `result` 返回数组；只接受第一个 HTTP(S) 地址。服务不可达、HTTP 失败或返回格式错误时展示错误，不回退到其他模式。

### 描述策略

- `none`：输出空描述。
- `filename`：使用原始文件名（去除扩展名）；链接使用 URL 的最后一段路径名。
- `custom`：使用设置中的固定描述文字。

设置会持久化并可跨窗口同步。切换模式时仅显示该模式需要的字段：自定义目录或 PicGo 地址。

## 模块边界

- Rust `image_import` 模块负责本地复制、相对路径计算、PicGo 请求和 Markdown 格式化所需元数据。
- Tauri 命令接收剪贴板图片字节、文件名、当前文档路径和配置；不让前端接触本地文件路径写入或网络上传细节。
- `Editor` 只提取粘贴数据、调用命令、以回调将 Markdown 插入当前选区。
- `Settings` 只编辑和保存配置；现有发布图片缓存保持独立。

## 验证

- 新安装配置默认为 `absolute`，且对应目录可创建。
- 本地绝对、自定义目录与相对路径分别复制图片并返回正确 Markdown 地址。
- 未保存文档选择相对路径时返回可读错误，文档内容不变。
- 模拟 PicGo 成功、服务错误和无效响应。
- 三种描述策略和直接粘贴 HTTP(S) 链接均产生正确 Markdown。
- 运行前端测试、Rust 测试、生产构建和差异检查。
